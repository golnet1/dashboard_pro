Виджеты

Потоковое видео

Потоковое видео

stream↑ к списку виджетов

Просмотр потокового видео с камер и других источников, включая ONVIF и RTSP.

Как работает

Поток показывается через серверный мост hls_bridge (ffmpeg), который пережимает источник в живой HLS и держит соединение при обрывах камеры. Для go2rtc используется встроенный HLS сервера go2rtc.

  • URL — прямая ссылка: http(s) на HLS (.m3u8), или rtsp:// (транскодируется на сервере).
  • Свойство — URL потока берётся из значения объекта.
  • go2rtc — хост (host:port) и камера из списка go2rtc; подключается напрямую.
  • ONVIF — полный поток RTSP камеры через сервис ONVIF: URL сервиса, логин и пароль. Режим «Показ»: Полный экран (весь кадр), Камера 1 / Камера 2 (одна из половин кадра для панорамных камер).

Управление камерой (PTZ)

Для источника ONVIF доступна настройка Управление камерой (PTZ) — полупрозрачная панель управления в правом нижнем углу виджета (показывается только на живом видео, в истории записей скрыта):

  • Крестовина из стрелок — поворот/наклон камеры: движение идёт, пока кнопка удерживается нажатой, и останавливается при отпускании.
  • Кнопки +/− (лупа) — приближение/отдаление (зум) по ONVIF, движение удержанием.
  • Кнопка ■ (стоп) — немедленная остановка поворота/зума.
  • Пресеты — сохранённые позиции камеры (если камера поддерживает): кнопка ⟳ обновляет список, кнопки с именами пресетов вызывают позицию.

Команды PTZ идут напрямую на камеру по ONVIF (сервис поворота), через сервер, где установлен модуль. Требуется логин/пароль ONVIF с правом управления камерой.

История (записи с SD)

Включите История и укажите базовый RTSP-адрес записей камеры (типовой путь камеры Hikvision/Dahua и совместимых), например rtsp://IP/ISAPI/streaming/channels/101/playback. На виджете появится кнопка ⏱, открывающая окно выбора интервала:

  • С / По — начальное и конечное время записей (локальное время).
  • Смотреть — начинает воспроизведение выбранного интервала; к URL добавляется ?starttime=…&endtime=… в формате YYYYMMDDTHHMMSSZ.
  • Назад к живому видео — возврат к обычному потоку.

Записи транскодируются тем же мостом hls_bridge одноразовой командой ffmpeg до конца выбранного интервала (запись ведёт себя как видео по запросу). Для просмотра нужен доступ камеры по RTSP к пути записей; заметки и формат URL показываются в настройках.

Перед запуском виджет проверяет камеру: если поток «записи» неотличим от прямого эфира (камера игнорирует диапазон и всегда отдаёт живое видео, например у некоторых дешёвых камер), воспроизведение не запускается — показывается сообщение «Записанных файлов не обнаружено». Кнопка «Всё равно показать» запускает поток вручную.

Дополнительно — снижение нагрузки

Настройки применяются при транскодировании через hls_bridge (ONVIF и RTSP через «URL»/«Свойство»).

НастройкаОписание
Качество (разрешение)Оригинал / 720p / 480p / 360p — пониженное разрешение снижает нагрузку на процессор сервера.
Ограничение кадров/сКак в источнике / 15 / 10 / 5 FPS — чем меньше, тем ниже нагрузка.

Для межсетевого экрана: мост работает на сервере, где установлен модуль; поток доставляется HLS-сегментами по HTTP.
